# Состояние приёмки ClimbPass 3

Актуализировано 03.11.2026. Локальная проверка завершена и принята пользователем. Production-релиз `dc7b712a67dc692e397196a3932aad5c574a9171` опубликован, публичная content-version — `3.0.0-dc7b712-a4f53fbc2415`.

## Подтверждено

- Проверки локального приложения: 36 модульных, 3 серверных и 7 браузерных сценариев; сохранение офлайн/после перезапуска, второе устройство, конфликты/ошибка записи, редактор, клавиатура, основные ширины и отсутствие пользовательских JSON-операций.
- На VPS: host Node 22.22.1, MySQL 8.4.11, раздельные пользователи runtime/build/deploy, закрытый env, сборка и миграция 001, непривилегированный backend systemd на loopback.
- Публичный HTTPS: точный NGINX host, локальная Host/SNI и публичная content-version, сохранённый wildcard, IPv4/IPv6 listeners. Внешняя доступность отдельно по каждому IP-семейству не заявляется.
- Пользователь подтвердил реальный Google-вход. Импорт в выбранный аккаунт сохранил 7 абонементов/29 посещений, все ID/даты/порядок/дубли и существующие программы.
- Штатный site-backup: первоначальные и post-import SQL/files копии, обратное чтение объектов с size/SHA-256/manifest. Из post-import копии восстановлены аккаунт, OAuth identity, сессия, operation/change/import receipt; восстановленная история сверена с исходником и владельцем.
- Изолированное восстановление не запускало application/OAuth/фоновые службы, рабочая БД не изменялась. Собственные временные БД/учётные записи удалены после успеха; артефакты сохранены отдельно для аудита.
- Обычный publisher выполнил свежий backup, проверил публичную/локальную готовность и записал первый успешный production-релиз.

Источники конкретных выводов пользователя, путей и backup-наборов ведутся в одном месте: [operations.md](operations.md). Связанные конфиги и SSH-направления описаны там же; сведения общего VPS принадлежат подключённой документации VPS и не переписываются без разрешения.

## Осталось

1. Опубликовать эксплуатационные инструменты/итоговую документацию отдельным коммитом и проверить ручной возврат между двумя успешными Node-релизами с возвратом на новый.
2. Установить ограниченный Actions→VPS ключ/authorized_keys/sudoers и подтвердить один автодеплой точного SHA; до этого production job выключен. Статус удалённого GitHub CI пока не подтверждён агентом.
3. Подтвердить пользовательское отображение импортированной истории, реальный межустройственный сценарий и установленную iOS/Android PWA/клавиатуру/safe area/VoiceOver/TalkBack. Локальная приёмка не подменяет эти проверки.
4. После завершения перехода привести project backup coverage к окончательному составу, исключив прежнюю static-версию из последующих регулярных копий; адресно разобрать временные restore/import artifacts. Автоматическая очистка соседних проектов или MySQL не поручалась.

## Пределы текущего решения

Полный JSON-граф пользователя хранится под транзакционной блокировкой; pull возвращает целый снимок. Tombstones/receipts не очищаются без отдельного совместимого протокола. Конфликты разрешаются выбором всей ожидающей ветки с локальным сохранением прежних редакций. Отзыв доступа не удаляет уже скачанные данные с офлайн-устройства. Кодовый rollback не откатывает схему/пользовательские данные. Создание полных SQL/files backup не объявляется единой атомарной точкой времени; восстановление кода/данных не является восстановлением всей ОС/TLS.
