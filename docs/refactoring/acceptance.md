# Отчёт реализации и проверок

Дата: 02.11.2026. Реализация ClimbPass 3 подготовлена локально по ТЗ 1.1. **Полная эксплуатационная приёмка и production-выпуск не завершены**: для них требуются OAuth credentials, настроенный VPS и реальные iOS/Android устройства.

## Что реализовано

- Чистая предметная модель, подменяемые календарь/время/ID, совместимость прежней схемы и правил.
- IndexedDB v1, атомарные graph/outbox/import journal, isolation по userId, Web Locks + generation + BroadcastChannel. Сетевой mutex отделён от локального: долгий POST не задерживает запись следующего поля.
- Google OIDC redirect/PKCE/state/nonce/JWKS, server-side sessions, verified email, allowlist на каждом API, CSRF/Origin, лимит тела, rate limit и HTTP security headers. В браузерных тестах сессии создаются напрямую только в тестовой БД; вход не обходится production-кодом.
- MySQL-миграция, атомарный push, блокировка строки пользователя, digest/idempotency receipts, revision tokens, tombstones и монотонный cursor. Независимые этапы объединяются; один этап, lifecycle, публикации, черновики, лимиты и второй запуск сохраняются конфликтом.
- Импорт legacy/v2/format2/raw keys, SHA-256/origin, preview и подтверждение аккаунта, durable journal и ID map; присоединение с отдельными ID, отказ от неоднозначного merge двух active pass, явный restore с expectedCursor.
- Export формата 3 с очередью/конфликтами/незаписанными полями, совместимый format2 для копирования, readonly snapshots и immutable publications.
- Редизайн главной, занятия, программ, редактора, истории, настроек, переноса и конфликтов. Локальные шрифты/иконки/лицензии, доступные подтверждения, сегменты, 90px swipe, сохранение маршрутов, native viewport/safe area.
- Воспроизводимая сборка, контентная версия, полный SW shell, исключение API/OAuth, CI, проектные backup/deploy/restore-test инструкции и скрипты. Деплой старого статического приложения не включается автоматически без серверной настройки.

## Открытая эксплуатационная приёмка

1. Настроить Google Cloud client и проверить реальный вход, отказ, отмену, истечение сессии и смену Google-аккаунта. Локально секретов нет, реальный OAuth-flow не выполнялся.
2. Выполнить CI на MySQL 8.4: workflow подготовлен, но не запущен из этой работы; локальная БД — MariaDB, это явно не доказательство результата MySQL 8.
3. Подготовить отдельный VPS service/env/NGINX/backup storage, staging-выпуск и реальный rollback процесса с проверкой версии. Проектный скрипт подготовлен; на реальном сервере не выполнялся.
4. Проверить установленную iOS/Android PWA, клавиатуру, safe area, реальный touch/pointercancel, VoiceOver/TalkBack, обновление прежней установленной PWA, blocked upgrade и многовкладочный UI на целевых браузерах. Chromium покрывает только часть этой матрицы.
5. Выполнить полную предметную/визуальную ручную приёмку по 13.1–13.5, включая два аккаунта с реальными Google-сессиями, все варианты управления очередью и длительный офлайн. Unit-тесты и синтетическая quota ошибка не доказывают все платформенные сбои.

## Осознанные ограничения первой реализации

- Физическое хранение графа — JSON под блокировкой пользователя; pull — полный атомарный snapshot. При большом объёме истории понадобятся нормализованные таблицы/страничный протокол. Receipts/tombstones нельзя чистить до такого изменения протокола.
- Разрешение конфликта выбирает **всю** локальную либо серверную ожидающую ветку после export. Оба полных состояния доступны, автоматического слияния текста нет; удобное предметное редактирование конфликтующих полей отдельно пока не реализовано.
- Два действующих абонемента при присоединении требуют отдельного решения, не архивируются автоматически. Оба исходника сохраняются; никакой частичный merge не активируется.
- Native dialog заменяет собственный BottomSheet focus trap. Даты отображаются полностью словами с годом вместо крупного дня из макета. Эти изменения и остальные адаптации перечислены в screens.md.
- Серверный отзыв не стирает уже скачанные данные. Локальные базы сохраняются после выхода и изолированы по аккаунтам; это не шифрование диска.

Commit, push, production deploy и импорт пользовательских данных в production не выполнялись. Текущее исходное дерево пользователя не сбрасывалось; до работы создана временная страховочная копия.

## Уточнение 03.11.2026: JSON исключён из пользовательского интерфейса

Убраны скачивание, копирование, импорт, восстановление и экран локального переноса. При конфликтах редакции отображаются обычным текстом; прежние состояния/очередь автоматически сохраняются в локальном журнале перед выбором. Выход не требует экспорта. Новые Google-аккаунты сразу получают исходные программы. Серверные резервные копии сохраняются.

Для обновления production подготовлен scripts/import-production-history.js: по умолчанию только preview; --apply выполняет атомарный, идемпотентный перенос history.json в указанный разрешённый аккаунт. Существующие абонементы/посещения не перезаписываются. Реальный production-перенос не выполнялся.

После изменения прошли 36 модульных, 3 серверных и 7 браузерных сценариев. Браузерный сценарий legacy-импорта заменён проверкой отсутствия JSON-интерфейса; сам перенос проверяется серверным тестом, включая повтор без дублей. Это уточнение заменяет предыдущие пункты отчёта о пользовательском экспорте/переносе и обязательном скачивании конфликтов.

03.11.2026 пользователь подтвердил завершение локальной проверки. Следующий этап — Google OAuth и серверный выпуск на https://climb-pass.app.shipachev.com/; подключение к VPS выполняет пользователь. Это не утверждение о выполненной проверке на устройствах или production. Дополнительно исправлен и проверен build каталога релиза без .git с явной передачей Git SHA.
